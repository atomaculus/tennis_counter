# PLAYCE - Play Console Data Safety Notes

Last updated: March 27, 2026

Use this file as the source of truth when filling the Play Console Data safety form. It must match the exact build being uploaded.

## Current codebase summary

- Match history is stored locally on device.
- Wear -> phone sync uses Google Play Services Wearable Data Layer.
- Premium entitlement uses Google Play Billing.
- Firebase Crashlytics and Firebase Analytics are included in the intended release track.

## Data safety alignment notes

Use this file as a consistency checklist, not as a substitute for reviewing the actual Play Console questionnaire.

Review at minimum:
- match and history data generated by the user
- purchase state associated with `premium_unlock`
- diagnostics collected by Firebase Crashlytics
- analytics or app interaction data collected by Firebase Analytics
- any identifiers or technical metadata attached to Firebase reporting

## Operational rules before submitting

- Verify the privacy policy and public website policy mention Firebase diagnostics and analytics in the same way the build is shipped.
- Confirm `google-services.json` and the Firebase project used for release are the intended production ones.
- Answer the Play Console Data safety form using the exact build that will be uploaded, not the repo in abstract.
- If Firebase event collection changes before launch, re-review this file and the policy files immediately.
- Keep the privacy policy URL and the Data safety answers consistent with each other.
- Re-check this file whenever billing, sync payloads, analytics, or third-party SDKs change.
