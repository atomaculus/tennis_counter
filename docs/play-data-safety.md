# PLAYCE - Play Console Data Safety Notes

Last updated: March 27, 2026

Use this file as the source of truth when filling the Play Console Data safety form. It must match the exact build being uploaded.

## Current codebase summary

- Match history is stored locally on device.
- Wear -> phone sync uses Google Play Services Wearable Data Layer.
- Premium entitlement uses Google Play Billing.
- Crash reporting is optional and controlled by `enableCrashlytics`.

## Recommended declaration by feature

### Always present in the shipped app

| Data type | Collected | Shared | Purpose | Notes |
|---|---|---|---|---|
| App activity: in-app interactions related to scoring and history | Yes | No | App functionality | Score, sets, timers, and match history are generated by the user inside the app. |
| App info and performance: app version and technical state needed for billing or sync flows | Yes | No | App functionality | Used locally by the app and Android framework components. |
| Financial info: purchase status for `premium_unlock` | Yes | Yes | App functionality | Purchase processing is handled by Google Play Billing. |

### Only if Crashlytics is enabled for the release build

| Data type | Collected | Shared | Purpose | Notes |
|---|---|---|---|---|
| App info and performance: crash logs | Yes | Yes | Analytics / diagnostics | Applies only when `enableCrashlytics=true` and Firebase is configured in the shipped build. |
| Device or other IDs used by Crashlytics | Yes | Yes | Analytics / diagnostics | Declare only if Crashlytics is active in the uploaded release. |

## Operational rules before submitting

- If `enableCrashlytics=false`, do not declare Crashlytics diagnostic collection in Play Console.
- If `enableCrashlytics=true`, verify the policy files mention diagnostics and that Firebase is configured in the actual build.
- Keep the privacy policy URL and the Data safety answers consistent with each other.
- Re-check this file whenever billing, sync payloads, analytics, or third-party SDKs change.
